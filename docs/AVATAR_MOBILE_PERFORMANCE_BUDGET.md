# Avatar mobile performance budget

These are **provisional acceptance targets**, not measured results. Device measurements are required before adoption as a release gate. The current avatar is 42.25 MiB; no Android device benchmark was performed in this phase.

| Resource | Initial target | Measurement / gate |
|---|---:|---|
| Bundled avatar GLB | ≤ 20 MiB | File size of release candidate; local/offline asset only |
| Rendered geometry | ≤ 100,000 triangles | Sum visible skinned meshes after export |
| Texture dimensions | ≤ 2048 px per side; prefer 1K where visually acceptable | Inspect all embedded textures; mipmaps generated by renderer |
| Texture payload | ≤ 12 MiB | Decoded and encoded payload reported separately |
| Deforming skeleton | ≤ 100 joints, including required fingers | Count skin joints; helpers excluded from exported skin |
| Facial morph targets | ≤ 80 initial target | Keep only channels needed for reviewed non-manual markers; verify runtime exports |
| Per-sign clip | ≤ 5 seconds and ≤ 250 keyframes per animated channel | Review timing and sampled keyframes; never reduce away meaningful sign motion |
| App-added peak memory | ≤ 150 MiB over idle baseline | Measure process PSS/RSS on target Android; include decoded textures and WebView |
| Cold local load | ≤ 5 seconds at p95 over 5 runs | Stopwatch/trace on target device, airplane mode enabled |
| Rendering | ≥ 30 FPS sustained at preview size | Capture frame timing during a 60-second signing playback |
| Concurrent avatar instances | 1 | Verify only one model viewer and one active clip are resident |

## Measurement protocol

1. Record device model, Android version, screen resolution, Flutter build mode, WebView version, battery/thermal state, and whether the device is offline.
2. Start from a force-stopped app. Measure the interval from opening Text to Sign until the model viewer's `load` event. Repeat five times and report median and p95.
3. Capture process memory before loading, at steady state, and during the longest approved sign sequence. Record the peak delta and whether it recovers after leaving the screen.
4. Record frame timing for a 60-second clip and report median, p95, and dropped frames. A desktop browser result is a separate platform result and cannot satisfy Android gates.
5. Repeat with a representative complete reviewed utterance; keep no more than one clip active. Check that pause, resume, stop, and sequence transitions do not create extra model instances.
6. Store raw measurement logs and candidate SHA-256 alongside the report.

## Current evidence

- Current GLB file size: 44,298,300 bytes / 42.25 MiB (PowerShell `Get-Item`). It exceeds the provisional 20 MiB target.
- Current structural test coverage checks GLB and rig data; it does not measure triangle count, decoded texture memory, frame rate, or loading latency.
- No replacement candidate was generated and no physical Android performance result exists. Do not infer performance from the asset file size or desktop preview.

The 20 MiB and other thresholds are starting budgets for a low-end Android target, not proof that any avatar meets them. Revisit after candidate export and Redmi Note 8 measurement.
